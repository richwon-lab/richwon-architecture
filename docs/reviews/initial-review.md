## 검토 방법

다음 제안은 작성자가 권장안을 채운 검토 대상입니다. 이미 확인된 핵심 요구인 사용 편의성, 직원의 업무 내용 편집, 자체 서버 장애 시 업무 지속, 서버 독립적인 공정 인계 자체를 다시 승인받기 위한 목록은 아닙니다.

각 항목에 ‘승인’, ‘수정 후 승인’, ‘보류’와 필요한 의견을 남깁니다. 예: `RV-03 승인`, `RV-02 서버와 앱은 하나의 구현 저장소로 수정`, `RV-06 참가자 수는 2명으로 조정`. 일부 항목만 먼저 검토할 수 있습니다.

RV-01 제품명과 RV-02 저장소 구성은 수정 후 승인되었습니다. RV-03~RV-11은 검토 대기입니다. 승인된 항목의 최종 결정은 이 목록에 남깁니다.

## 결정 기록

### RV-01 — 제품명 확정

- 검토일: 2026-11-21
- 검토자 역할: 프로젝트 요청자
- 결과: 수정 후 승인
- 최종 결정: 제품명은 `R-edit`, 한국어 표기는 `알에딧`으로 통일한다.
- 변경 이유: 기존 명판 자동화 프로그램의 이름을 유지하면서 명판 관련 업무 전반으로 지원 범위를 확장한다.
- 대체한 제안: 제품명 `Richwon` 및 한국어 설명 `리치원 업무 시스템`을 제품명으로 사용하는 제안.
- 적용 범위: README, 프로젝트 개요, 문서 목록, 업무 연속성 명세의 제품명과 AGENTS.md.
- 영향 제외: 저장소 이름·구성, 기술 선택 및 다른 검토 항목은 이번 결정으로 승인하지 않는다.
- 반영 상태: 문서 반영 완료. 커밋은 생성하지 않음.

### RV-02 — 설계·관리와 구현 저장소 분리

- 검토일: 2026-11-21
- 검토자 역할: 프로젝트 요청자
- 결과: 수정 후 승인
- 최종 결정: `richwon-architecture`에서 공통 요구사항·아키텍처·연동 계약·프로젝트별 구현 항목을 관리한다. 아키텍처의 책임과 연동 경계에 따라 구현 프로젝트를 구분하고 각각 별도 저장소로 관리한다.
- 변경 이유: 각 구현 프로젝트의 작업 범위를 자체 저장소와 공통 관리 문서로 한정하고, 여러 구현 프로젝트의 연동 조건과 진행할 항목을 한곳에서 확인한다.
- 후속 결정: 구현 프로젝트의 수와 이름은 아키텍처 정의 후 결정한다. 원격 저장소의 공개 범위는 별도 검토한다.
- 반영 문서: README, DOC-OVERVIEW, DOC-GOV, DOC-INDEX.
- 반영 상태: 문서 반영 완료.

추가 결정은 대상 ID, 검토일, 검토자 역할, 결과, 최종 내용·변경 이유, 반영 문서·커밋 순서로 기록한다.
