## 현재 작업

- **현재 단계** — 첫 도입 범위와 인수 기준을 정하고 있다. 업무 흐름, 대표 시나리오와 예외, 공통 요구사항과 도안 품질 후보를 정리했다. 구현과 인수 시험은 시작 전이다.
- **문서 검토** — README, 문서 목록, 프로젝트 개요 검토를 마쳤다. 다음은 [회사 기본 정보](business/company-profile.md)를 [문서 점검표](documentation-guide.md#9-문서-점검표)로 검토한다.
- **다음 제품 결정** — [초기 검토 목록](reviews/initial-review.md)의 RV-05에서 첫 도입 범위를 정한다. 도안 자동화 우선, 자료 인계 우선, 두 업무를 제한적으로 함께 도입하는 안을 [대표 업무와 예외](business/scenarios.md)에 대입해 비교한다. 도안 자동화를 한 대의 PC에서 먼저 도입할 수 있는지 살피고, 범위를 바꿀 만한 현장 차이만 확인한다.
- **이미 확정한 사항** — 공통 설계·관리 저장소와 구현 저장소는 분리한다. [RV-02 결정 기록](reviews/initial-review.md#rv-02--설계관리와-구현-저장소-분리)

## 프로젝트 마일스톤

아래는 단계별 완료 기준 초안입니다. 컴퓨터 사용 경험이 거의 없는 신규 담당자의 독립적인 업무 수행과 직원의 고객별 규칙 설정은 공통 핵심 요구사항으로 적용합니다. 도안 자동화와 자료 인계의 첫 도입 범위는 RV-05에서, 장애 중 유지해야 할 작업과 인계 범위는 RV-08에서 검토합니다.

| 마일스톤                           | 다음 단계로 넘어가는 조건                                                                                                                                                                                                                 | 확인 근거                                                         |
|------------------------------------|-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|-------------------------------------------------------------------|
| **1. 첫 도입 범위 확정 · 진행 중** | 대표 업무와 주요 예외를 기준으로 첫 도입에 포함할 업무와 후속으로 미룰 업무를 결정한다. 공통 핵심 요구사항과 해당 업무의 인수 기준을 합의한다.                                                                                            | 대표 시나리오와 예외, 범위 결정 기록, 요구사항과 인수 기준        |
| 2. 아키텍처와 구현 경계 확정       | 후보 구조가 합의한 업무와 적용되는 장애 시나리오를 충족하는지 검토한다. 구성요소별 책임, 공유 데이터와 연동 경계, 프로젝트별 구현 범위를 결정한다. 구조 선택을 막는 쟁점은 이 단계에서 해소한다.                                          | 시스템 구성도, 시나리오별 검토 결과, 아키텍처 결정 기록           |
| 3. 상세 설계 완료                  | 구현할 업무의 화면과 데이터, 입출력, 필요한 연동, 실패·재시도 동작을 정한다. 요구별 시험에서 무엇을 확인하고 어떤 결과를 합격으로 볼지 정한다. 구현을 막는 설계 쟁점을 해소한다.                                                          | 상세 설계, 연동 계약, 요구 ID별 시험 사례와 기대 결과             |
| 4. 첫 도입 범위 구현·검증          | 첫 도입 범위의 인수 기준을 충족한다. 신규 담당자가 대표 업무를 독립적으로 완료하고, 담당 직원이 코드 수정이나 재배포 없이 고객별 규칙을 적용할 수 있는지 확인한다. 도안 품질·자료 인계·장애 대응은 첫 도입에 합의한 범위에 따라 검증한다. | 요구 ID별 시험 환경과 결과, 직원 평가 기록, 잔여 문제의 처리 결정 |
| 5. 현장 도입 및 운영 인수          | 실제 환경에서 설치·업데이트·복구를 확인한다. 검증 결과를 근거로 도입 여부와 운영 책임을 결정하고, 도입하는 경우 업무·운영 담당자가 사용과 장애 대응 절차를 인수한다.                                                                      | 현장 확인 결과, 도입 결정, 운영 인수 기록                         |

단계 종료 기록에는 판정 근거, 확인한 역할과 잔여 항목의 처리 결정을 남기는 안을 검토합니다. 단계 전환 절차와 역할 배정은 RV-11과 RV-03에서 확인합니다.
