## 프로젝트 마일스톤

첫 도입의 목표는 컴퓨터 사용 경험이 거의 없는 직원도 조작 도움 없이 담당 업무를 끝내고 다음 공정에 자료를 넘길 수 있게 하는 것입니다. 인터넷과 직원 PC가 정상일 때는 자체 서버 장애 중에도 합의된 업무와 인계를 이어갈 수 있어야 합니다.

아래는 일정과 상세 범위를 정하기 위한 계획 초안입니다. 각 단계에서 필요한 결정을 검토 기록에 남기고 관련 요구나 설계 문서에 연결합니다.

| 마일스톤                           | 완료 기준                                                                                                                                                                         |
|------------------------------------|-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **1. 첫 도입 범위 확정 · 진행 중** | 대표 흐름과 주요 예외를 대조하고, 도안 개선과 인계의 포함 범위, 해당 도안 품질·사용성·장애 대응 기준을 합의한다. 근거는 업무 시나리오, 범위 결정 기록, 요구·인수 기준이다.        |
| 2. 아키텍처와 구현 경계 확정       | 정상·장애 흐름에서 요구를 충족하는지 검토하고, 구성요소 책임·연동 경계·프로젝트별 구현 항목을 합의한다. 근거는 구성도, 시나리오별 검토 결과, 주요 결정 기록이다.                  |
| 3. 상세 설계 완료                  | 화면·입출력·데이터 관계·결과 버전·연동 계약·실패 및 재시도·기대 결과가 구현 가능한 수준으로 정해지고, 구현을 막는 설계 문제가 해소된다. 근거는 상세 설계와 요구 ID별 검증 사례다. |
| 4. 첫 도입 흐름 구현·검증          | 합의한 범위의 도안 결과, 실제 직원의 독립 수행, 자체 서버 장애 중 업무·인계를 검증한다. 시험 환경·결과·미해결 항목의 처리 결정을 요구 ID에 연결한다.                              |
| 5. 현장 도입                       | 설치·업데이트·복구를 실제 환경에서 확인하고, 검증 결과를 근거로 도입 여부와 운영 책임을 결정한다. 근거는 현장 시험과 운영 인수 기록이다.                                          |

단계 종료 시 확인한 산출물, 판정 근거, 검토 역할, 차단 항목과 잔여 항목의 처리 결정을 남긴다. 단계 전환과 역할의 적용 방식은 RV-11과 RV-03에서 검토한다.

## 현재 작업

- **현재 검토** — README부터 정식 문서를 한 편씩 [문서 점검표](documentation-guide.md#9-문서-점검표)로 검토한다.

- **다음 작업** — RV-05에서 도안 자동화 우선·인계 우선·제한 결합을 비교한다. [대표 업무와 예외](business/scenarios.md)의 기존 기록을 사용하고 범위에 영향을 주는 현재 차이만 확인한다.
- **확정 사항** — 제품명 R-edit / 알에딧(RV-01), 공통 설계·관리와 구현 저장소 분리(RV-02).
- **준비 상태** — 현재 업무 기록과 대표·예외 시나리오, 공통 요구와 도안 품질 후보가 있다. 실행 코드와 현 제품 인수 시험 결과는 없다.
