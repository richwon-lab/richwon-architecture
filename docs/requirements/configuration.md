# 업무 설정 및 편집 요구사항

문서 ID: SRS-CONFIG · 상태: 검토 중 · 내용 책임: 제품 책임자 · 개정: 0.1 · 2026-11-21

## CFG-001 — 개발 변경 없는 업무 내용 편집

**요구 상태:** 핵심 요구 확인. 세부 범위·권한·삭제 처리는 검토안.

**요구:** 직원은 서비스가 지원하는 업무 정보·규칙·양식을 화면에서 추가·수정·삭제할 수 있어야 한다. 고객별 규칙을 관리할 때는 화면에서 지원되는 작업·검사 방식을 선택하고, 고객별 적용 조건을 추가하거나 변경할 수 있어야 한다. 직원이 관리하는 값과 규칙은 코드 수정이나 프로그램 재빌드·재배포 없이 변경하고 적용할 수 있어야 한다.

**업무상 이유:** 고객·자재·제작 조건의 변경은 업무 운영 중 발생하며, 매번 개발자가 배포해야 한다면 직원의 직접 운영이 불가능하다.

| 업무 영역의 예시 | 직원 작업 | 추가할 업무 명세 |
| --- | --- | --- |
| 자재·업체 | 항목 추가·수정·삭제 | 필수값, 참조 관계, 중복 처리 |
| 고객별 도안 규칙 | 고객과 조건·동작 선택, 결과 확인 | 적용 순서, 충돌, 예외 |
| 명판 템플릿 | 외형·홀·글자 배치 편집과 저장 | 편집 범위, 정밀도, 파일 호환 |
| 매뉴얼 | 사진·설명 작성과 수정 | 열람·편집·변경 이력 |
| 업무 입력 항목 | 추가, 이름 변경, 순서 조정 | 기존 값과 양식 변경의 관계 |
| 제작·전송 설정 | 지원하는 설정 선택과 시험 | 장비·목적지·시험 조건 |

이 표는 지원할 작업의 성격을 설명한다. 여섯 개로 기능 수를 한정하거나 첫 도입에 전부 포함하지 않는다.

> **검토 주석 RV-07 · 범위 경계안:** 기존 기능이 제공하는 값·조건·배치·양식의 변경은 사용자 편집으로 제공하고, 새 장비 프로토콜이나 새로운 가공 알고리즘의 추가는 개발 변경으로 분류합니다. 실제 변경 사례를 이 기준에 대입해 편집 범위가 지나치게 좁거나 복잡하지 않은지 검토합니다.

**인수 기준 초안:** 직원이 같은 앱 버전에서 고객별로 지원되는 검사 규칙을 선택하고 조건을 추가·수정·삭제한 뒤 해당 고객 작업에 반영되는지 확인한다. 코드 수정·재빌드·재배포 없이 완료한다. 지원 대상별 편집을 함께 확인하고 삭제 방식은 CFG-003, 사용성은 UX-001을 따른다.

## CFG-002 — 변경 결과 확인과 적용

**요구 상태:** 제안.

> **검토 주석 RV-07:** 고객 규칙·템플릿·제작 설정은 저장 전에 예제 결과를 확인하는 방식을 제안합니다. 단순 업체 연락처 수정에도 무조건 별도 승인 절차를 요구하지 않습니다. 진행 중인 작업은 변경 당시의 기준을 유지하고, 새 작업부터 새 기준을 적용하는 것을 기본안으로 제안합니다.

**요구:** 결과물이나 제작 조건에 영향을 주는 변경은 적용 대상과 결과를 확인할 수 있어야 한다. 기존 작업에 새 기준을 적용할 때에는 명시적인 재적용 동작을 제공해야 한다.

**업무상 이유:** 기준을 수정한 뒤 진행 중인 작업의 결과가 조용히 바뀌는 상황을 방지한다.

**인수 기준 초안:** 기존 작업을 만든 뒤 규칙을 변경하면 기존 작업은 유지되고 새 작업에는 변경값이 적용된다. 기존 작업에 재적용하면 변경 영향이 표시된다. 규칙별 결과 확인의 상세 동작은 업무 명세에서 정의한다.

## CFG-003 — 참조 중인 정보의 삭제

**요구 상태:** 제안.

> **검토 주석 RV-07:** 작업 이력이 참조하는 자재·업체·템플릿 등은 ‘사용 중지’로 처리하여 새 선택에서 제외하고 과거 기록은 유지합니다. 아직 사용되지 않은 초안은 삭제를 허용하는 방식을 제안합니다. 사용자 화면에서 삭제와 사용 중지의 차이를 설명해야 합니다.

**요구:** 정보의 제거가 기존 작업의 식별과 이력 확인을 깨뜨려서는 안 된다.

**인수 기준 초안:** 사용 중지된 항목은 새 작업 선택에서 제외되지만 기존 작업에서 확인할 수 있다. 미사용 초안을 삭제했을 때 관련 없는 자료가 제거되지 않는다.

## 검증 상태 및 후속 설계

모든 항목 미실시. 편집 가능 여부를 직원 직급만으로 결정하지 않는다. 업무별 편집 책임을 확인하고 권한 명세를 작성한다. 실제 도입 대상으로 선정한 업무부터 별도 요구사항 문서로 구체화하고 이 공통 명세를 참조한다.
