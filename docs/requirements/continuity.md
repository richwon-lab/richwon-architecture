# 업무 연속성 및 공정 간 인계 요구사항

문서 ID: SRS-CONTINUITY · 상태: 검토 중 · 내용 책임: 제품 책임자 · 개정: 0.2 · 2026-11-21

## 용어와 장애 경계

- 자체 서버: R-edit 운영을 위해 관리하는 중앙 시스템. 구체적인 서버 수와 배치 방식은 이 용어로 결정하지 않는다.
- 공정 인계: 다음 담당자가 작업을 이어갈 수 있도록 필요한 자료와 업무 정보를 전달하는 행위.
- 인터넷 전체 장애: 고객 이메일 등 외부 서비스 접근도 제한되는 상황. 복구를 기다리는 운영을 허용한다.
- 자체 서버 장애: 인터넷과 작업 PC는 정상이나 자체 서버에 접근하거나 서비스를 이용할 수 없는 상황.

공정 인계는 CNC 장비에 가공 파일을 보내는 작업과 동일하다고 가정하지 않는다. 장비 전송은 대상과 실패 영향이 다르므로 해당 기능 범위가 정해지면 별도 명세로 정의한다.

## BCP-001 — 자체 서버 장애 중 업무 지속

**요구 상태:** 핵심 요구 확인. 지속 업무의 상세 범위는 검토안.

**요구:** 인터넷과 직원 PC가 정상인 상황에서는 자체 서버 장애만을 이유로 업무를 중단하지 않아야 한다.

**업무상 이유:** 직원의 작업 수행과 공정 진행이 중앙 시스템의 단일 장애에 묶이지 않도록 한다.

> **검토 주석 RV-08 · 지속 범위안:** 이미 받은 자료로 진행 중인 작업의 조회·편집·저장·인계를 우선 보장하고, 장애 중 수신한 새 주문 자료로 작업을 시작하는 경우도 포함하는 것을 제안합니다. 중앙 집계·전체 이력 검색·공통 기준의 신규 배포는 복구 이후로 지연할 수 있도록 제안합니다. 이 구분은 원래의 업무 지속 요구를 제한하는 선택이므로 승인 전에는 확정 예외로 취급하지 않습니다.

**인수 기준 초안:** 인터넷과 필요한 PC 간 통신을 유지한 상태에서 자체 서버 접근을 차단한다. 진행 중 작업과 새 자료 수신 시나리오를 수행하여 결과 저장과 다음 공정 인계가 가능한지 확인한다. 필요한 과거 자료의 범위는 대표 업무로 검증한다.

> **검토 주석 RV-09 · 인증 운영안:** 기존에 등록·인증된 업무 PC는 서버 장애 중 앱을 재시작해도 합의된 업무를 계속할 수 있도록 제안합니다. 신규 PC 등록과 권한 변경은 서버 복구 후 처리하는 방향입니다. 권한 철회 지연과 장애 중 인증 유지 기간의 균형은 인증 설계에서 별도 검토합니다. 무기한 로그인 허용이나 특정 토큰 방식을 확정하지 않습니다.

## BCP-002 — 서버에 독립적인 공정 인계

**요구 상태:** 핵심 요구 확인. 완료 기준과 부재 처리 방식은 검토안.

**요구:** 다음 공정으로 자료를 전달하는 작업은 자체 서버의 정상 가동에 의존해서는 안 된다.

**업무상 이유:** 같은 공정 내 공동 편집보다 다음 담당자에게 전달하는 작업이 생산 흐름 유지에 중요하다.

> **검토 주석 RV-08 · 전달 완료안:** 수신 측에서 실제 자료와 업무 정보를 확보한 상태를 ‘전달 완료’로 정의합니다. 발신 PC에 전송 요청을 저장한 상태는 ‘전달 대기’로 구분합니다. 수신 PC가 꺼져 있으면 자료와 요청을 보존하고, 다시 연결된 후 이어서 전달하는 방식을 제안합니다. 수신 담당자의 작업 착수는 별도 상태입니다.

**인수 기준 초안:** 자체 서버가 차단된 상태에서 발신자가 자료를 전달하고 수신자가 해당 자료를 열어 다음 작업을 시작할 수 있다. 수신 PC가 꺼진 경우 완료로 표시하지 않고, 다시 켜진 후 자료를 누락·중복 없이 전달한다.

PC 간 직접 통신·공유 폴더·외부 중계 중 어떤 방식을 사용할지는 아키텍처에서 대안을 비교한다. 단순히 서버 파일의 URL만 전달하여 서버 장애 중 열 수 없다면 요구를 충족하지 못한다.

## BCP-003 — 복구 후 결과 보존과 전달 이력

**요구 상태:** 제안.

> **검토 주석 RV-08:** 장애 중 저장한 결과는 복구 후에도 보존하고, 같은 인계의 재전송이 새로운 작업으로 중복 등록되지 않도록 제안합니다. 전달 후 변경본은 이전 전달과 구별하여 수신자가 변경 여부를 알 수 있게 합니다. 자동 덮어쓰기는 기본 동작으로 제안하지 않습니다.

**요구:** 서버 복구와 통신 재시도가 이미 완료한 작업을 소실시키거나 동일 인계를 중복 작업으로 만들지 않아야 한다.

**인수 기준 초안:** 장애 중 편집·인계 후 서버를 복구하고 재시도를 발생시켜 결과의 보존, 동일 인계 중복 방지, 수정본 구분을 확인한다. 충돌을 감지한 경우 처리되지 않은 상태를 사용자에게 표시한다.

## 검증 상태와 후속 작업

모든 항목 미실시. 허용 장애 기간, 보관량, PC 고장과 네트워크 분할, 백업·복구 목표는 정상·장애 시나리오를 작성하는 아키텍처 단계에서 수치와 책임을 제안하고 검토한다. 이 문서가 PC 자체 고장에도 무손실을 보장하는 것은 아니다.
