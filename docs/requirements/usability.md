# 사용성 요구사항

문서 ID: SRS-USABILITY · 상태: 검토 중 · 내용 책임: 제품 책임자 · 개정: 0.1 · 2026-11-21

## 적용 범위

일반 직원이 수행하는 업무 입력·조회·수정·인계와 직원에게 제공하는 업무 설정 기능에 적용합니다. 개발자용 도구의 사용 편의성으로 대체하지 않습니다.

사용 편의성은 제품의 최우선 품질 목표입니다. 실제 사용자는 개발 지식이 없으며 컴퓨터·문서 작업의 숙련도가 낮을 수 있습니다.

## UX-001 — 일반 직원의 독립적인 업무 수행

**요구 상태:** 핵심 요구 확인. 평가 조건과 수치는 검토안.

**요구:** 컴퓨터 사용 경험이 거의 없고 해당 업무를 처음 맡는 직원도, 다른 사람이 화면에서 무엇을 해야 할지 하나씩 알려주지 않아도 담당 업무를 이해하고 완료할 수 있어야 한다.

**업무상 이유:** 기능의 존재만으로 업무에 도입할 수 없으며, 수행할 때마다 개발자가 개입하면 일반 직원이 직접 사용하는 업무 시스템의 목적을 충족하지 못한다.

> **검토 주석 RV-06 · 평가안:** 사무·생산 업무를 대표하는 직원 3명 이상을 대상으로, 업무별 기본 안내 후 대표 작업 3건을 평가합니다. 평가 중에는 진행자가 다음 클릭을 알려주지 않습니다. 모든 참가자가 최종 결과까지 완료하고, 잘못된 고객이나 자료를 다음 공정에 넘기는 중대 오류가 없어야 한다는 기준을 제안합니다. 참가자 수·교육량·시나리오 수는 조정 가능합니다. 소규모 현장 평가이며 통계적 사용성 인증을 의미하지 않습니다.

**인수 기준 초안:** 합의된 교육과 시험 자료가 주어진 상태에서 각 참가자가 업무를 완료한다. 성공 여부, 도움 요청, 잘못된 선택, 소요 시간과 수정 과정을 기록한다. 진행자의 조작 개입이 필요하면 실패로 기록하고 개선 후 다시 확인한다. 시간은 최초 평가에서 기준선을 측정하고 후속 목표를 정한다.

**관련:** UX-002, UX-003, CFG-001, BCP-002.

## UX-002 — 업무 단계와 결과의 이해

**요구 상태:** UX-001을 구체화한 제안.

> **검토 주석 RV-06:** 다음 항목을 화면 검토와 직원 평가의 기준으로 제안합니다. 구체적인 화면 배치나 컴포넌트를 강제하지 않습니다.

**요구:** 직원이 현재 작업 대상, 수행할 행동, 저장·전달 결과를 구분할 수 있어야 한다. 같은 업무 개념에는 일관된 이름을 사용하고 내부 시스템 용어를 노출하지 않는다.

**업무상 이유:** 대상이나 처리 상태를 잘못 이해하면 중복 입력, 누락, 잘못된 자료 전달이 발생할 수 있다.

**인수 기준 초안:** 대표 업무의 주요 단계에서 참가자가 현재 대상과 다음 행동을 설명할 수 있다. 전달 요청과 전달 완료가 구분되어 표시되고 참가자가 그 차이를 이해한다. 판정 방법은 실제 행동과 사후 확인을 함께 사용한다.

## UX-003 — 입력 오류의 수정

**요구 상태:** UX-001을 구체화한 제안.

> **검토 주석 RV-06:** 직원이 잘못 입력한 위치와 수정 방법을 파악하고 기존 입력을 보존한 채 수정하는 동작을 기본 기준으로 제안합니다. 모든 업무 변경의 무제한 되돌리기를 요구하는 것은 아닙니다.

**요구:** 유효하지 않은 입력으로 작업이 실패하면 수정 대상과 필요한 조치를 알려주고, 정상적으로 입력한 나머지 값을 다시 입력하지 않도록 해야 한다.

**인수 기준 초안:** 대표 필수값 누락·형식 오류를 발생시켰을 때 직원이 오류 위치를 찾고 수정하여 완료한다. 불필요한 전체 재입력이 발생하지 않는다. 적용할 입력 규칙은 업무 명세에서 정의한다.

## 검증 상태

모든 항목 미실시. 실제 직원과 업무 자료로 평가한 결과는 아직 없다. 합격 기준 승인 후 검증 계획과 결과를 요구 ID로 연결한다.
