# 대표 업무와 예외 시나리오

문서 ID: BUS-SCENARIOS · 상태: 검토 중 · 작성일: 2026-11-21

## 1. 활용 원칙

아래 흐름을 기준으로 현재 운영에서 달라진 부분과 범위 판단에 필요한 누락을 확인한다. 자료 표기와 확인 수준은 [현재 업무 흐름](current-workflow.md#6-근거와-확인-수준)을 따른다.

주 시나리오는 기존 자료를 합친 현재 업무 설명이다. 실제 발주 원본부터 납품까지 일치하는 단일 주문 기록을 이미 확보했다는 의미는 아니다. 분석용 흐름으로 시작하고, 한 사례의 실제 자료가 필요할 때 최소한으로 대조한다.

## 2. SCN-01 기존 디자인을 이용한 명판 작업 — 종합 흐름

**목적:** 문구와 수량이 있는 주문을 도안으로 준비하고 생산 담당자가 사용할 자료로 넘긴다.

**기반:** S03 3·8절 및 BUS-WORKFLOW. 구체적인 고객·작업일·품목 수는 지정하지 않음.

**전제:** 사용할 기존 디자인 또는 도안이 있고 고객의 문구·수량을 확인할 수 있다. 접수자와 도안자가 동일인일 수 있다.

| 순서 | 수행자 역할 | 행동 | 결과 또는 확인점 | 현재 지식 수준 |
| --- | --- | --- | --- | --- |
| 1 | 도안 담당자 | 고객 발주와 첨부를 확인하고 누락 조건 확인 | 문구·규격·재질·수량·납기 등 | 기존 업무 자료 있음 |
| 2 | 도안 담당자 | 작업지시서를 작성·분배하고 필요한 디자인을 구분 | 지시서와 디자인별 작업 | 기존 업무 자료 있음 |
| 3 | 도안 담당자 | 기존 자료를 찾아 제작 조건과 비교 | 재사용할 디자인·파일 | 검색 방식의 실제 화면은 미확인 |
| 4 | 도안 담당자 | 같은 디자인의 문구를 준비 | 소량은 직접 입력/복사, 대량 동일형은 Excel 활용 | 기존 업무 자료 있음 |
| 5 | 도안 담당자 | 기존 도구로 생성·편집 | 줄바꿈·자폭·크기·홀 간섭 확인 | 수작업 잔존 기록 있음 |
| 6 | 도안 담당자 | 문구·수량·파일을 확인하고 Type3 마무리 | 생산에 사용할 VND 및 필요한 파일 | 기존 업무 자료 있음 |
| 7 | 도안 담당자→생산 담당자 | 발주 전체 도안과 지시서를 인계 | 생산자가 대상을 찾아 작업 가능 | 정상 전체 인계, 긴급 일부는 예외 |
| 8 | 생산 담당자 | 새/잔여 자재 선택과 배치 | 작업할 원판과 배치 | 과거 운영 기록 있음 |
| 9 | 생산 담당자 | NC 생성·기계 전송·세팅·가공 | 가공된 명판과 작업 확인 | 연결·현재 순서는 변경 여부 확인 |
| 10 | 후공정 담당자 | 필요한 마감·포장·납품 | 고객에게 전달할 제품 | 세부 담당·완료 조건 확인 필요 |

**다음 공정 인계의 관찰점:** 도안 작성자가 ‘넘겼다’고 생각한 시점, 생산자가 자료를 확인하는 방법, 작업방 파일을 옮기는 의미, 수정 도안이 오면 이전 자료를 어떻게 구분하는가. 전체 흐름을 다시 설명받지 않고 이 차이만 확인한다.

**요구 연결:** UX-001~003, CFG-001, BCP-001~003. 도안 품질은 [도안 자동화 요구 후보](../requirements/design-automation.md)의 DFT-001~005에서 검토한다.

## 3. 기존에 확보된 대표 사례

| ID | 자료와 사례 | 이미 알고 있는 내용 | 아직 주장할 수 없는 내용 |
| --- | --- | --- | --- |
| SCN-02 | 75×25mm 단일 영역 디자인의 발주 추출 자료(S04 38~49절 시험 기록) | 문구 286행을 줄바꿈·패턴 비교에 사용. 해당 디자인의 4.5mm·80%·선호 1~3줄 사례 | 286행=286개 생산 수량, 모든 주문에 동일 조건 적용, 납품 완료 확인 |
| SCN-03 | 100행 복수 영역 스프레드시트(S04 38~43절 시험 기록) | NO·문구·RAT의 3영역, 기록상 해당 열 빈칸 없음 | 고객·수량·자재·가공 방식 확정 |
| SCN-04 | 한 줄 고정 타이틀 디자인 | 고정 한 줄은 참고 결과에서도 두 줄로 바꾸면 안 됨. 극단 문구는 방어 시험으로 사용 | 극단 문구가 실제 주문에서 흔함, 모든 타이틀의 치수·폰트 동일 |
| SCN-05 | 기존 디자인 소량 주문 시험안 | 3종 4개 가상 예시로 과거 배치·새 문구·수동 줄바꿈·수량 출력 비교 | 실제로 접수·납품된 주문, 현장 소요 시간 측정 완료 |

SCN-02·03의 근거는 기존 설계 검토서에 기록된 입력 구조다. 실제 시험에는 권한이 있는 원본 또는 동등한 검증 자료를 준비한다.

## 4. 정상 흐름에 붙일 변형·예외

| ID | 상황 | 확인할 업무 판단 또는 기대 결과 | 근거/상태 |
| --- | --- | --- | --- |
| EX-01 | 한 발주에 여러 디자인·재질·작업 종류 | 디자인별 작업을 구분하되 발주 전체와 연결 | S03 현재 업무 |
| EX-02 | 같은 문구가 반복되고 수량이 다름 | 행을 임의 합치거나 제거하지 않고 총수량 유지 | S03 과거 요구 |
| EX-03 | 예비용 빈 명판·빈 텍스트 영역 | 의도적인 공란을 단순 누락으로 차단하지 않음 | S03·S04 과거 요구 |
| EX-04 | 재주문·기존 제품 일부 교체 | 과거 배치 유지와 현재 기준 신규 생성의 구분 | S03·S04 과거 요구 |
| EX-05 | 긴 문구가 홀·외곽·가공 기준에 맞지 않음 | 필수 조건을 몰래 완화하지 않고 확인 필요 결과 구분 | S04 과거 요구·시험 |
| EX-06 | 사람이 전체 줄바꿈을 지정 | 다른 자동 개행 추가 금지, 자동 복귀는 명시적 동작 | S04 최신 과거 요구 |

| EX-08 | 다른 고객 주문을 같은 원판에 합배치 | 같은 자재 조건과 고객·프로젝트 소속 보존 | S06 과거 운영 기록 |
| EX-09 | Type3에서 출력 이후 수정 | 내부 저장 배치와 최종 파일 차이를 인식 | S03·S04 과거 요구 |
| EX-10 | 인계 후 수정 도안·수량 변경 | 수신자의 착수 여부와 이전 자료 구분 | 현재 전달 요구로부터 도출한 확인 시나리오; 현 운영 미확인 |
| EX-11 | 자체 서버만 중단 | 합의한 작업과 다음 공정 인계 지속 | 현재 BCP 핵심 요구; 구체 방식은 제안 |

현재 업무를 확인하는 질문과 새 제품의 동작을 정하는 질문을 섞지 않는다. EX-10~12의 해결안을 실제로 운영 중인 것처럼 작성하지 않는다.

## 5. 최소 추가 확인 목록

다음은 모두 한 번에 질문할 목록이 아니다. 기존 자료와 실제 파일에서 먼저 채우고, 그 시점의 결정에 필요한 질문만 한다.

| ID | 이미 채운 내용 | 남은 확인 | 확인이 필요한 이유 |
| --- | --- | --- | --- |
| Q-01 | 발주 전체 도안 완료 후 생산 인계, 긴급 일부 예외, 작업방 이동은 시작 의미 | 지금도 같은지, 바뀌었다면 달라진 부분 | 완료·전달·착수 상태의 잘못된 설계 방지 |
| Q-02 | 기존 R-edit의 문구·격자 생성과 줄바꿈·자폭 수작업 | 현재 버전에서 이미 해결된 기능은 무엇인지 | 이미 있는 기능 재개발 방지 |
| Q-03 | 실제 도안 시험 사례와 원문·수량 보존 원칙 | 첫 개선 목표: 도안 수정 감소, 인계 개선, 또는 제한된 결합 | RV-05 범위 선택 |
| Q-04 | VND·지시서 중심 인계, 파일 공유 사용 | 생산자가 ‘이 자료로 시작해도 된다’고 판단하는 표시·행동 | 인계 완료와 최신본 기준 |
| Q-05 | G1/G2 네트워크 폴더, G3 FTP의 과거 경로 | 현재 연결 방식에 변화가 있는지 | 장비 연동 검토 시에만 필요 |
| Q-06 | 마감·포장·납품 단계 존재 | 담당자가 받는 정보, 검수 시점과 완료 판단 | 해당 공정을 첫 범위에 넣을 때만 필요 |

첫 인터뷰는 SCN-01의 요약을 제시하고 Q-01의 차이부터 확인하는 안을 권장한다. 변경이 없으면 기존 기록을 사용한다. 실제 업무를 측정하는 단계가 오기 전에는 시간·클릭 수·모든 고객 예외를 새로 조사하도록 요구하지 않는다.

## 6. 업무 사례 완료의 판단

‘업무 사례 문서가 작성됨’은 현장 검증 완료가 아니다. M1에서는 흐름과 범위 판단에 영향을 주는 차이가 해소되고 관련 요구·예외가 연결되면 된다. 제품 인수 시험 단계에서는 실제 자료, 실행 환경, 관찰 결과를 별도 기록한다.
