# R-edit

**리치원컴퍼니의 명판 제작 업무를 연결하는 사내 업무 시스템**

R-edit은 직원이 작업에 필요한 자료를 확인하고, 고객별 제작 기준을 적용하며, 다음 공정으로 결과물을 전달하도록 지원합니다. 컴퓨터에 익숙하지 않은 직원의 사용 편의성과 자체 서버 장애 시 업무 연속성을 핵심 품질 목표로 삼습니다.

이 저장소는 R-edit의 업무 범위, 요구사항, 아키텍처, 연동 계약과 구현 프로젝트별 작업 항목을 관리합니다. 현재는 요구사항 정의 단계입니다.

제품명은 **R-edit**, 한국어 표기는 **알에딧**입니다. 기존 명판 자동화 프로그램의 이름을 유지하며 명판 관련 업무 전반으로 지원 범위를 확장합니다. 회사명은 리치원컴퍼니입니다. 제품명 결정은 [RV-01 결정 기록](docs/reviews/initial-review.md)에 기록합니다.

## 시작하기

1. [프로젝트 개요](docs/project-overview.md)에서 목적, 사용자, 업무 범위와 도입 방향을 확인합니다.
2. [문서 목록](docs/index.md)에서 현재 문서와 상태를 확인하고 담당 업무와 관련된 요구사항을 읽습니다.
3. [초기 검토 목록](docs/reviews/initial-review.md)의 제안 사항을 검토합니다. 승인되지 않은 제안을 구현의 확정 조건으로 취급하지 않습니다.
4. 문서를 수정하기 전에 [문서 관리 규칙](docs/documentation-guide.md)을 확인합니다.

문서는 UTF-8 Markdown으로 작성합니다. 편집기 또는 GitHub에서 읽을 수 있으며, 문서 검토를 위한 애플리케이션 빌드나 SDK 설치는 필요하지 않습니다.

## 핵심 설계 기준

- **직원의 사용 편의성:** 기술 지식이나 높은 컴퓨터 숙련도를 전제로 하지 않습니다.
- **업무 변경의 자율성:** 지원되는 업무 정보·규칙·양식은 직원이 직접 추가·수정·삭제할 수 있어야 합니다.
- **업무 연속성:** 인터넷과 직원 PC가 정상일 때 자체 서버 장애로 업무가 중단되지 않아야 합니다.
- **공정 간 인계:** 다음 공정으로 자료를 전달하는 기능은 자체 서버의 가동 여부에 의존하지 않아야 합니다.

요구사항의 상세 조건과 인수 기준은 [문서 목록](docs/index.md)에 연결된 각 명세에서 관리합니다.

## 저장소의 책임

| 포함 | 포함하지 않음 |
| --- | --- |
| 업무·사용자·범위 정의 | 실제 고객 주문서와 생산 파일 원본 |
| 제품 요구사항과 품질 기준 | 비밀번호·접속 토큰 등 인증정보 |
| 시스템 구성과 공정별 자료 흐름 | 직원용 운영 매뉴얼의 실시간 원본 관리 |
| 프로젝트별 구현 항목과 공통 연동 계약 | 구현 프로젝트의 소스 코드·테스트·배포 설정 |
| 주요 결정의 근거와 대안 | 애플리케이션 빌드 결과물 |
| 문서 목록과 검토 기록 | 일반적인 업무 파일 공유 |

구현 프로젝트는 아키텍처에서 책임과 경계를 정한 뒤 별도 저장소로 관리합니다. 각 프로젝트는 자체 저장소와 이 관리 저장소의 문서를 참조해 구현과 연동을 진행합니다. 저장소 구성 결정은 [RV-02 결정 기록](docs/reviews/initial-review.md#rv-02--설계관리와-구현-저장소-분리)에 기록합니다.

## 개발 진행 방식

요구사항 정의 → 아키텍처 설계 → 상세 설계 → 구현·검증 → 도입·운영 순으로 진행합니다. 앞 단계의 판단이 바뀌면 관련 요구와 설계를 함께 갱신합니다. 단계별 검토 기준은 [문서 관리 규칙](docs/documentation-guide.md)에 정의합니다.

현재 검토 대상은 제품 기본 정보, 초기 도입 범위, 요구사항의 인수 기준입니다. 서버 구성과 프레임워크 선택을 먼저 고정하지 않습니다.

## 참여 및 문의

업무 범위와 우선순위는 제품 책임자, 기술 설계와 구현은 개발 담당자, 업무 적합성 평가는 실제 사용자와 함께 검토합니다. 초기에는 프로젝트 요청자가 제품 책임자와 개발 담당자 역할을 겸하는 구성을 제안합니다.

> **검토 주석 RV-03 · 역할 제안:** 실제 역할 배정과 변경·검토 절차는 [문서 관리 규칙](docs/documentation-guide.md)을 기준으로 검토합니다. 요청자의 이름·계정·연락처는 임의로 기재하지 않습니다.

요구 변경이나 문서 오류는 관련 문서 ID와 항목 ID를 포함해 제안합니다. 초기 검토 의견은 [검토 목록](docs/reviews/initial-review.md)에 기록합니다.
