# R-edit (알에딧)

**리치원컴퍼니의 명판 도안과 제작 업무를 지원하는 사내 업무 시스템**

직원은 작업 자료를 확인하고 고객별 제작 기준에 맞춰 명판 도안을 준비한 뒤, 생산 담당자에게 필요한 자료를 넘깁니다. R-edit은 이 과정에서 문구 배치와 같은 반복 작업을 줄이는 것을 목표로 합니다.

현재는 첫 도입 범위와 인수 기준을 정하는 단계입니다.

## 시작하기

1. [현재 작업](docs/index.md#현재-작업)에서 진행 중인 검토와 다음 작업을 확인합니다.
2. [프로젝트 개요](docs/project-overview.md)에서 제품의 목적, 사용자, 업무 범위를 파악합니다.
3. [문서 목록](docs/index.md)에서 맡은 업무에 필요한 명세와 검토 기록을 찾습니다.

## 공통 핵심 요구사항

- **처음 맡는 직원도 업무를 완료** — 컴퓨터 사용 경험이 거의 없고 해당 업무를 처음 맡는 직원도, 다른 사람이 화면에서 무엇을 해야 할지 하나씩 알려주지 않아도 담당 업무를 이해하고 완료할 수 있어야 합니다.
- **고객별 작업·검사 규칙을 직원이 관리** — 직원은 화면에서 지원되는 작업·검사 방식을 선택하고, 고객별 적용 조건을 추가하거나 변경할 수 있어야 합니다. 직원이 관리하는 규칙은 코드 수정이나 프로그램 재배포 없이 적용할 수 있어야 합니다.

요구사항의 상세 조건과 인수 기준은 [문서 목록](docs/index.md)에 연결된 각 명세에서 관리합니다.

## 공통 설계 원칙

**기능이 늘어도 변경 범위를 파악할 수 있는 구조** — 구성요소마다 맡은 책임과 연결 방식을 명확히 합니다. 같은 업무 규칙이 여러 곳에 반복되면 공통으로 관리할 범위를 검토합니다. 기능을 추가하거나 변경할 때 수정할 위치와 영향을 받는 기존 동작을 파악할 수 있어야 합니다.

## 저장소의 역할

- **이 저장소**에는 업무 문서, 요구사항과 품질 기준, 시스템 설계와 연동 계약, 프로젝트별 구현 항목과 주요 결정의 근거를 둡니다.
- **구현 저장소**는 시스템 설계에서 정한 프로젝트 경계에 따라 나눕니다. 소스 코드·테스트·배포 설정은 각 구현 저장소에서 관리하며, 구현과 연동에 필요한 공통 기준은 이 저장소에서 확인합니다. [RV-02 저장소 구성 결정](docs/reviews/initial-review.md#rv-02--설계관리와-구현-저장소-분리)

이 저장소에 작업 예시가 필요하면 공개 가능한 자료를 사용합니다. 실제 고객 주문서, 생산 파일 원본, 인증정보는 별도로 관리합니다.

## 개발 진행 방식

요구사항 정의 → 아키텍처 설계 → 상세 설계 → 구현·검증 → 현장 도입 순으로 진행합니다. 다음 단계로 넘어가기 전에 완료 기준을 확인하고, 주요 결정과 근거를 관련 문서에 남깁니다.

단계별 산출물과 완료 기준은 [프로젝트 마일스톤](docs/index.md#프로젝트-마일스톤)에서 확인합니다.
